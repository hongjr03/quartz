我一直觉得要彻底理解 Algorithm W 非常困难，所以写下这篇文章，帮助自己更好地理解它。希望它对你也有帮助。

这篇文章适合已经接触过具有类型推断的语言（如 Haskell、OCaml 或 Rust）并对其工作原理感兴趣的读者。理解本文不一定需要先熟悉这些语言，但有所了解会更容易。

我不会讨论理论部分，也不会证明 Algorithm W 为什么有效。我更关心它到底在做什么，以及为什么这么做。

文末有术语表和其他资源链接，其中也包括最初提出 Algorithm W 的论文。

## 语言

Algorithm W 针对的是一种简单的编程语言。它非常精简，连 if 语句或数据结构都没有。但它又足够复杂，能展示类型推断中需要用到的各种技巧。即使把这门语言扩展出更多特性，仍然有可能用这些技巧来推导类型。

这是一种纯函数式语言，风格和 ML 系语言相似。语言中的一切，甚至函数定义，本身都是表达式。事实上，程序就是一个单独的表达式。

这种语言允许的表达式大致有：

- 字面量值，比如 `123` 或 `false`。
- 变量。
- 函数应用，也就是函数调用。
- 函数抽象，也就是函数声明。
- let 绑定。

### 语法

任何表达式都可以加上括号，以显示正确的结合方式。

字面量的语法和你预期的一样，比如 `55` 或 `true`。变量也是如此，比如 `x` 或 `foobar`。

函数应用稍微不同一些。假设你有一个函数 `plus`。用 `x` 和 `y` 调用它，只需写成 `plus x y`。如果你想先用 `x` 调用函数 `g`，再把结果传给 `f`，就必须写成 `f (g x)`。`(f (g x))` 当然也可以。从某种意义上讲，`plus x y` 实际上按 `(plus x) y` 的方式分组，不过这一点后面还会再说到。

函数抽象会给单一参数命名（为什么只能是一个参数？稍后再说），后跟一个句点和函数体表达式。比如 `x.plus 1 x` 表示一个把 1 加到输入数字上的函数。这样写不会给函数起名字。常见的写法是把函数定义包在括号里。函数体里也可以再放另一个函数，比如 `x.y.plus x y`（它会按 `(x.(y.(plus x y)))` 分组）。

let 绑定为一个变量命名、指定其值对应的表达式，然后计算一个使用该变量的表达式。例如：`let square = (x.times x x) in square 10`。

下面大致是这个语法的 BNF：

```text
PROGRAM := EXPR

EXPR
  := LITERAL
  |  VARIABLE
  | '(' EXPR ')'
  | ABSTRACTION
  | APPLICATION
  | LET

LITERAL := INTEGER | BOOLEAN

INTEGER := DIGIT+
DIGIT := '0'..'9'

BOOLEAN := 'true' | 'false'

VARIABLE := LETTER+
LETTER := 'a'..'z' | 'A'..'Z'

ABSTRACTION := VARIABLE '.' EXPR

APPLICATION := EXPR EXPR

LET := 'let' VARIABLE '=' EXPR 'in' EXPR
```

### 语义

变量既可以引用值，也可以引用函数。变量有两种引入方式：let 绑定，或者函数参数。变量声明可能会遮蔽已有声明。如果发生这种情况，子表达式中的变量名会引用新的变量，而在该表达式之外，旧变量仍然可访问。注意，在 `let x = plus x 1 in x` 这样的 let 绑定里，`plus x 1` 使用的是旧的 `x` 定义，而 `in x` 引用的是新定义。（为了简洁起见，本文假设已有内建函数，比如 `plus`。）

函数通过闭包捕获声明时所在作用域中的变量。这就是为什么尽管这个语言表面上只有单参数函数，却仍然能够实现多参数函数。比如：

```text
let hypotenuse = (x.(y. sqrt (times x x) (times y y)))
in hypotenuse 5 10
```

`hypotenuse` 是一个函数：它先接收一个数字作为参数 `x`，然后返回另一个函数。这个第二个函数同样接收一个数字作为参数 `y`，但它返回的是一个数字。当这个函数像 `hypotenuse 5 10` 这样调用时，实际意思是“先把 `hypotenuse` 应用到 5 上，再把结果应用到 10 上”。它的结合方式是 `(hypotenuse 5) 10`，括号里的那部分会先求值。

把所有函数都设计成只接收一个参数，会让类型推断更简单，因为它不需要单独的逻辑去检查传入参数的个数。这也意味着你可以对函数做部分应用，例如：

```text
let double = times 2 in double 10
```

因为把 `2` 应用到 `times` 上会得到另一个函数，所以完全可以把这个函数绑定到名字上，之后再使用它。

语义上最后还要指出一点：递归调用在语法上被禁止了（函数名不会在函数定义内部被绑定，所以函数没有办法引用自己）。不过，还是可以借助 [fixed-point combinator](https://en.wikipedia.org/wiki/Fixed-point_combinator) 把非递归函数变成递归函数，只是这个类型系统实际上无法处理 fixed-point combinator。

## 类型系统

类型集合里包含一些基础类型，比如 `int` 和 `bool`。

还有一种函数类型，它把输入类型和输出类型用中缀的 `->` 连接起来。例如：`int -> int` 表示接收一个整数并返回一个整数的函数。`(int -> int) -> int` 表示接收一个从 `int` 到 `int` 的函数，并返回一个整数的函数。`int -> (int -> int)` 本质上是一个接收两个整数并返回另一个函数的函数，但更严格地说，它是一个接收整数并返回一个从 `int` 到 `int` 的函数。

除了这类具体类型之外，还有类型变量。（它们通常写成一个字母，比如 `a`、`b`，有时也会是字母加数字，比如 `a0` 或 `v2`。）把它们想成代数里的变量，而不是编程里的变量：变量最终会有某个值（我们暂时还不知道是什么）。例如，`a -> a` 是一个函数类型，它接收某种东西（我们没说明是什么类型），并返回同一种类型的东西（也就是最后会是什么类型就是什么类型）。

所以，一个类型要么是：

- 一个具体类型，比如 `int` 或 `bool`。
- 一个类型变量，比如 `a` 或 `b`。
- 一个函数类型 `t1 -> t2`，包含另外两个类型。

这个语言没有类，也没有用户自定义结构，因此没有办法用类型来表示它们。

类型变量带来了类型推断中更有意思的一点：泛型。先看恒等函数（也就是那个只把参数原样返回的函数）：`(x. x)`。它的类型是 `a -> a`。这里之所以要写成类型变量 `a`，是因为光看函数定义，我们无法知道 `x` 到底是什么类型。不过，在任何实际调用里，`x` 都会有某种类型。比如我们把它作用到一个整数上：

```text
let id = (x.x) in id 123
```

输入类型在这里就变成了整数。假设我们还想把这个整数结果用于别的计算：

```text
let id = (x.x) in square (id 123)
```

我们怎么知道 `(id 123)` 会求值成适合的类型呢？这就要用到类型变量 `a -> a`。我们知道输入类型是 `int`，于是把它与函数类型匹配，发现只要把 `a` 替换成 `int` 就能让输入类型成立。当我们把一个类型变量替换成某个类型时，那个变量在所有位置都会被替换。这里也就意味着类型里的两个 `a` 都会变成 `int`。结果是 `int -> int`，即我们知道这个函数返回整数。

不过，刚才的说法稍微有一点不准确。我们并非直接把类型变量 `a` 替换。先看一个会出问题的例子：

```text
let id = (x. x) in (id square) (id 123)
```

这里我们把 `square` 传给 `id`（它什么也不改变），同时把 `123` 传给 `id`（同样什么也不改变）。从程序输出看，它基本等价于 `let id = (x. x) in square 123`，甚至等价于 `square 123`。

但从类型角度就有意思了。假设 `square` 的类型是 `int -> int`。第一次调用 `id` 时，它的类型应该是 `(int -> int) -> (int -> int)`；而第二次调用时，它又需要是 `int -> int`。如果我们把 `a -> a` 里的 `a` 替换，那么应该替换成这两个类型中的哪一个呢？无论选哪个，都会让 `id` 的另一次使用出错。

实际做法是：在每次使用 `id` 时，都把它的类型“实例化”一次。也就是说，把类型中某些类型变量替换成新的类型变量（这些新变量名以前没有用过）。因此，与其尝试把 `a` 替换成两个相互冲突的类型，我们不如对 `id` 的类型进行两次实例化，分别得到第一次调用的 `b -> b` 和第二次调用的 `c -> c`。然后，把 `b` 替换成 `(int -> int)`，让 `(id square)` 的类型成立，再把 `c` 替换成 `int`，让 `(id 123)` 的类型成立。

还要注意另一点：和 Java 或 C++ 这类语言不同，这个类型系统没有任何子类化的概念。事实证明，子类化会给类型推断算法带来很多麻烦。

## 类型推断

### 合一与替换

#### 无限类型

> [!note]
> 第一次阅读这篇文章时，可以先跳过这一节，之后再回来。

一种制造无限类型的简单方式是 `(f.f f)`。这种写法在这里不太好读，所以我把它改写成 Python：

```python
def something(f):
    return f(f)
```

这类例子很有意思，因为即使我们无法给 `f` 写出一个（有限的）类型，但实际上如果把某些值传给 `f`，程序也确实可能正常运行而不会崩溃。（比如把恒等函数传进去就没问题。）

假设我们已经知道这个函数的类型是：

```text
type_of_f -> type_f_returns
```

既然我们知道 `f` 也必须是个函数，就可以把 `type_of_f` 分成 `argument_of_f` 和 `type_f_returns`，于是得到：

```text
(argument_of_f -> type_f_returns) -> type_f_returns
```

看看能不能找出 `argument_of_f` 是什么。我们把 `f` 作为参数传给了 `f`，所以参数的类型必须和 `f` 本身的类型一样。好，试试看：

```text
((argument_of_f -> type_f_returns) -> type_f_returns) -> type_f_returns
```

这并没有消掉 `argument_of_f`。继续展开会得到：

```text
((((argument_of_f -> type_f_returns) -> type_f_returns) -> type_f_returns) -> type_f_returns) -> type_f_returns
```

这就是类型变成无限的原因。固定点组合子遇到的正是这种无限类型问题。

#### 替换与组合

把替换应用到具体类型上（比如 `int` 或 `bool`）时，会原样返回那个类型。

把替换应用到类型变量上时，有两种情况：

1. 如果这个类型变量有对应的替换，就返回那个替换结果。例如，如果类型变量是 `c`，替换是 `{c: bool}`，就返回 `bool`。
2. 如果替换里没说明这个类型变量该怎么办，就保持原样。例如，如果类型变量是 `b`，而替换只有 `{c: bool}`，那它会返回 `b`。

把替换应用到函数类型上，就是把替换分别应用到左边和右边，然后再构造出一个新的函数类型。（这个过程会递归进行。）

现在可以更准确地描述“组合”或“合并”替换是什么意思了。假设有两个替换 `S1` 和 `S2`。由这两个替换组合出来的替换，应该和先后应用这两个替换的效果完全一样。也就是说，如果 `S3 = compose_substitutions(S1, S2)`，那么 `apply(S3, t)` 应该和 `apply(S2, apply(S1, t))` 结果相同。

举个例子：假设 `t` 是 `a -> b`，`S1` 是 `{b: c -> int}`，`S2` 是 `{a: bool, c: float}`。把 `S1` 应用到 `t` 上会得到 `a -> (c -> int)`。再把 `S2` 应用到这个结果上，会得到 `bool -> (float -> int)`。

一个看似合理但不正确的定义是：把两个替换中的映射直接合并。如果两个替换都提供了同一个类型变量的替换，就以左边那个替换为准。

这个定义已经很接近了，但还差一点。如果直接合并得到 `S3 = {b: c -> int, a: bool, c: float}`，当我们把这个替换应用到 `a -> b` 上时，得到的是 `bool -> (c -> int)`。问题在于，我们漏掉了把 `c` 替换成 `float`。

正确做法是：把两个替换 `S1` 和 `S2` 组合时，先把 `S1` 应用到 `S2` 里所有替换类型上，然后把 `S1` 中所有替换加进来，除非 `S2` 已经包含了那个变量的替换。

### 合一

合一是很少几行代码，却又是整个类型推断算法的核心。类型错误是在这里发现的，类型信息也是在这里被学到的。可以说，类型推断算法的其他部分，都是为了给合一函数准备数据，以及利用它的结果。

它是一个算法，用来判断要修改什么，才能让两个类型变得相同。如果最后发现做不到，那就意味着类型错误。它唯一允许做的事情，就是把类型变量替换成别的东西（也可能是另一个类型变量）。这意味着，如果两个类型不一样，那就必须得有某些类型变量可以改。

对已经相同的类型做合一，比如 `int` 和 `int`，不会做任何事。对明显不同的类型做合一，比如 `int` 和 `bool`，或者 `bool` 和 `a -> bool`，会得到类型错误。

真正发生变量替换，是在一边是变量、另一边是别的东西的时候。例如，把 `int` 和 `a` 合一，会得到把 `a` 替换成 `int`。若两边都是类型变量，比如 `a` 和 `b`，那就把左边替换成右边。

替换是一个从类型变量到替换内容的映射。例如，我们可以把 `a` 替换成 `b -> b`，把 `c` 替换成 `int`。从现在开始，我会把这种替换写成 `{a: (b -> b), c: int}`。我们可以把替换应用到类型上，也就是在类型里查找需要替换的类型变量并把它们替换掉。把上面的替换应用到 `a -> (b -> c)` 上，结果会是 `(b -> b) -> (b -> int)`。

合一算法（假设成功）会返回一个能让两个类型相同的替换。换句话说，如果合一算法对类型 `t1` 和 `t2` 返回替换 `S`，那么 `apply(S, t1) == apply(S, t2)`。

假设两个类型是 `int -> a` 和 `b -> bool`。合一算法先合一左边，也就是 `int` 和 `b`。这会得到替换 `{b: int}`。然后它再合一右边，也就是 `a` 和 `bool`，得到替换 `{a: bool}`。接着把这两个结果组合起来，返回 `{a: bool, b: int}`。把这个替换应用到任意一个输入类型上，都会得到同一个类型：`int -> bool`。

再看 `a -> a` 和 `int -> c`。先合一左边：`a` 和 `int`。这会得到替换 `{a: int}`。关键在这里：在继续之前，我们必须把右边函数类型中的另一个 `a` 也替换成 `int`。于是，合一完左边之后，两个类型就变成了 `int -> int` 和 `int -> c`。现在可以合一右边了：`int` 和 `c`。这会得到替换 `{c: int}`。最后，把两个替换组合起来，就得到 `{a: int, c: int}`。

还有两种特殊情况：

1. 如果两边是同一个类型变量，结果只是空替换 `{}`，因为不需要做任何修改。
2. 不允许把一个类型变量替换成包含它自己的类型。比如，不允许把 `a` 替换成 `a -> b`。这种情况下会触发类型错误，也就是 occurs check。

### 方案与泛化

scheme（也叫 type scheme，类型方案）是给类型额外附加一条信息后的结果。这个额外信息是一个类型变量列表。列表中的类型变量是该类型中出现的类型变量的子集。

恒等函数 `(x. x)` 的类型是 `a -> a`。但如果把恒等函数存到变量里：

```text
let id = (x. x) in ...
```

变量 `id` 的类型实际上是一个类型方案：`Scheme([a], a -> a)`。任何变量的类型都是用类型方案来表示的，不管它是不是函数。

每次使用 `id` 时，我们都会拿到它的类型方案 `Scheme([a], a -> a)`，并把其中所有出现在 scheme 列表里的类型变量替换成新的类型变量。这个过程会产生一个类型，而不是一个 scheme。`id` 的第一次使用可能会实例化成 `a0 -> a0`，第二次使用可能会实例化成 `a1 -> a1`。

类型方案是基于某个类型和类型环境中的信息创建出来的。真正需要知道的是，应该怎样选出那个类型变量列表。方法很简单：列出该类型里所有不出现在类型环境中的类型变量。

类型环境本质上就是我们已经拥有类型且仍在作用域中的那些东西。下面这个例子更容易说明：

```text
(x. let f = (y. x) in f 123)
```

重点看 `f` 的类型。它是一个函数，所以类型必然是函数类型。它的参数类型是什么？什么都有可能，所以我们用一个类型变量来表示。为了方便阅读，把这个类型变量叫作 `t_y`。返回类型呢？那就是 `x` 的类型，把它记作 `t_x`。因此 `f` 的类型就是 `t_y -> t_x`。

当我们把 `f` 用在 `123` 上时，参数类型会从 `t_y` 变成 `int`，但返回类型不会变，仍然是 `t_x`。这意味着，在实例化 `f` 的类型时，我们只把 `t_y` 替换成新的类型变量，而保留 `t_x` 不变。换句话说，用类型方案来表示就是 `Scheme([t_y], t_y -> t_x)`。

为什么只列出 `t_y`，而不是 `t_y` 和 `t_x` 都列出？因为 `t_x` 出现在类型环境里。`x` 是在 `f` 外部定义的，它的类型是 `t_x`，所以即使 `t_x` 出现在 `t_y -> t_x` 这个类型里，它仍然会被排除在类型方案变量列表之外。

只有通过 `let` 绑定创建出来的变量才会被泛化。函数参数不会被泛化（它们的类型方案列表总是空的）。

总结一下：

- scheme 由一个类型和若干附着在该类型上的类型变量组成。
- 声明变量时，会对它的类型做泛化。
- 泛化就是从一个类型生成一个 scheme。
- scheme 中的类型变量，是那些存在于类型里、但不在类型环境里的变量。
- 使用变量时，会对它做实例化。
- 实例化一个类型方案会产生一个类型。
- 这个类型就是把类型方案里的类型变量替换成全新的类型变量之后的结果。

### 表达式的类型推导

类型推断函数接收两个参数：要推导类型的表达式，以及当前的类型环境。类型环境是一个从变量名（语言中的变量名，不是类型变量）到类型方案的映射。它包含当前作用域里的变量。当我们开始为一个程序寻找类型时，类型环境一开始是空的。算法会在执行过程中不断把内容加进去。

这个函数还会返回两个结果：表达式的类型，以及一个替换。可以把这个替换看成算法返回的“关于程序其他部分学到了什么”的一种方式。

这个算法会递归地遍历表达式树。当一个表达式里包含其他表达式时，算法会分别对这些子表达式递归调用自己。有时算法会把一个修改过的类型环境传给递归调用。这个修改过的副本确实只是副本；原始环境保持不变。

#### 字面量

字面量最简单。我们只需要返回这个值对应的类型（比如 `false` 返回 `bool`，`123` 返回 `int`），以及一个空替换。

#### 变量

变量也不难。我们在类型环境里查找这个变量名，得到它对应的类型方案。有了类型方案之后，就对它做实例化，得到类型。我们返回这个类型，以及一个空替换。如果类型环境里没有这个变量，那就说明变量未定义，这是一个错误。

要注意的是，实例化发生在变量被使用的时候，而不是在函数被应用的时候。

#### 函数抽象

记住，在这个语言里函数只有一个参数。我们会创建一个新的类型变量来表示那个参数。假设参数是 `x`，新类型变量是 `v0`。然后，我们创建一个新的类型环境，把 `x` 加到传入的类型环境中。当 `x` 被加入时，它的类型会设为 `Scheme([], v0)`。

接着，使用这个更新后的类型环境，对函数体做递归调用。这个调用会返回一个替换和一个类型。

然后，我们把刚刚得到的替换应用到前面创建的那个类型变量 `v0` 上。这样，如果函数体的类型推导学到了什么关于参数类型的信息，就会反映在这个类型变量最终被替换成了什么。

现在可以构造函数类型了。参数类型就是把替换应用到类型变量之后得到的结果。返回类型则是函数体的类型。算法返回这个函数类型，以及函数体类型推导得到的那个替换。

#### 函数应用

在求函数应用的类型时，我们不能把函数的返回类型直接当成整个表达式的类型。考虑把一个数字（类型 `int`）传给恒等函数（类型 `a -> a`）的情况。由于恒等函数会把输入原样返回，返回值显然应该是 `int`，而不是类型 `a`。

步骤如下：

1. 创建一个新的类型变量，用来捕获函数的返回类型。
2. 递归调用，求函数本身的类型，得到替换 `sub1` 和类型 `type1`。
3. 创建一个新的类型环境，把 `sub1` 应用到环境里所有类型上。
4. 使用更新后的类型环境求参数表达式的类型，得到 `sub2` 和 `type2`。
5. 把 `sub2` 应用到 `type1` 上。
6. 用第 1 步创建的类型变量，构造函数类型：参数类型是 `type2`，返回类型是这个新类型变量。
7. 调用合一算法，让函数的类型和这个构造出来的函数类型合一。
8. 把 `sub1`、`sub2` 和合一得到的 `sub3` 组合起来。
9. 把第 1 步中的类型变量应用 `sub3`，得到整个函数应用表达式的结果类型。

简要总结：假设函数的类型是 `t1 -> t2`，参数的类型是 `t3`。引入一个新类型变量 `v4`，把 `t1 -> t2` 和 `t3 -> v4` 做合一。看看 `v4` 最终被替换成了什么，那就是整个表达式的类型。

#### let 绑定

let 绑定例如 `let x = 123 in x`。

1. 先求第一个表达式的类型，得到 `sub1` 和 `type1`。
2. 创建新的类型环境，把 `sub1` 应用到当前环境中所有类型上，然后用这个环境把 `type1` 泛化成类型方案。
3. 创建新的类型环境，把这个类型方案绑定给变量。
4. 再创建新的类型环境，把 `sub1` 应用到步骤 3 的环境中所有类型上。
5. 用这个环境求第二个表达式的类型，得到 `sub2` 和 `type2`。

函数的结果是 `type2` 以及 `sub1` 与 `sub2` 的组合。

这里有一个重要的点：通过 `let` 绑定引入的内容可以实例化成不同类型，而函数参数引入的内容不能。比如下面这个表达式能工作：

```text
let id = (x. x)
in (id square) (id 44)
```

但下面这个不行：

```text
(id. (id square) (id 44)) (x. x)
```

函数参数在所有使用位置都必须拥有同一种类型，而通过 let 绑定创建的变量则可以被实例化成不同类型。

这种做法也避免了自引用/递归绑定。实现很简单：先给第一个表达式求类型，此时变量名还未加入类型环境。这样，第一个表达式里若出现该变量名，引用的是同名的旧绑定，而非 `let` 语句正引入的变量。

例如，表达式

```text
let x = 5
in let x = square x
   in x
```

的结果是 25。

## 总结

这就是这个算法的工作方式。它会针对不同种类的表达式，分别使用我们前面介绍的不同类型操作。

处理字面量时，不涉及任何类型操作。

变量需要在类型环境里查找，并执行实例化操作。

函数抽象会涉及创建一个新的类型变量、修改类型环境，以及应用替换。

函数应用也会涉及创建一个新的类型变量并应用替换。此外，它还会用到合一算法，并对替换进行组合。

let 绑定则会同时用到泛化操作、修改类型环境，以及应用和组合替换。

为后面这三种表达式求类型时，还会递归地调用算法处理子表达式。

## 注记

### 最一般合一子

这个算法里的合一，被称为返回“最一般合一子”（most general unifier）。它基本上意味着它会返回尽可能一般的类型（或者更准确地说，返回一个能得到尽可能一般类型的替换）。可以把它理解成：为了让两个类型匹配，它只做尽可能少的改动。

举个例子，假设我们要合一类型 `a -> a` 和 `b -> c`。一种可能的合一结果是 `{a: int, b: int, c: int}`。这确实能让两个类型统一起来（结果都是 `int -> int`），但它不是最一般的。一个可能的最一般合一子是 `{b: a, c: a}`（结果都是 `a -> a`）。另一个可能的是 `{a: c, b: c}`（结果都是 `c -> c`）。

最一般合一子的一个有趣性质是，你可以通过再应用一个替换，从它给出的类型得到这两个类型的任何其他合一结果。

### 术语表

- **Abstraction**: 创建一个函数。
- **Application（of substitutions）**: 把某些类型变量替换成别的类型。
- **Application**: 调用一个函数。
- **BNF**: [Backus-Naur form](https://en.wikipedia.org/wiki/Backus%E2%80%93Naur_form)
- **Binding**: 创建一个变量。
- **Generalize**: 从一个类型创建一个类型方案。
- **Identity function**: 只返回自身参数的函数。
- **Instantiate**: 从一个类型方案创建一个类型。
- **New type variable**: 创建一个在别处没有使用过的类型变量。
- **Scheme**: 见“Type scheme”。
- **Substitution**: 从类型变量到其替换类型的映射。
- **Type environment**: 当前作用域中所有变量的类型方案。
- **Type scheme**: 一个附带类型变量列表的类型。
- **Type variable**: 类型系统里存放某种类型的变量。
- **Unifier**: 一个能让两个类型变成相同的替换。
- **Variable**: 语言中存放某个值的变量。
